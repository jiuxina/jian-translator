# Windows 输入与流式结果修复（2026-11-19）

全局快捷键在去抖前只接受 `ShortcutState::Pressed`；释放事件不改变去抖时间，首次按下也不受启动时的初始时间抑制。

划词送往主页面时携带同一个请求 ID。页面未就绪时保存 `{ text, id }`，前端接受请求后立即写入 `__itSelectionAccepted`；后续原生重试在进入翻译处理器前直接退出，因此不会重复清空附件、覆盖用户编辑或发起翻译。每次重试仍受原生请求代次检查约束。

Windows 剪贴板文本读取先查询 `GlobalSize`，拒绝零长度、非 UTF-16 整数长度的内存，再构造最多 200001 个 UTF-16 单元的有界切片。只接受切片内有 NUL 终止符的内容；没有终止符时返回空结果。锁定成功的内存总会解锁，已经打开的剪贴板总会关闭。

划词浮窗使用与共享 Web 相同的 `translation-stream.js` 传输实现，令牌预算按输入长度计算。流式文字在确认正常完成前只供预览，不能复制；截断、错误和不完整结束显示明确失败，迟到结果由请求代次和取消信号拦截。错误信息作为文本节点插入。

`it_debug_log` 在 Release 构建中不访问文件系统。Debug 构建串行写入，单次最多 1024 个非控制字符；活动日志达到 256 KiB 后保留一份前次日志并截断活动文件。

定向验证入口：`node tests/verify-windows-input.mjs`。测试读取仓库源码并执行真实的划词投递脚本，覆盖未就绪、确认、重复投递及编辑保留，同时检查快捷键、剪贴板和日志边界契约。它不读取真实剪贴板、不运行原生窗口、不访问临时日志。实际 Windows Tauri/WebView2 构建、快捷键长按和畸形剪贴板内存的原生验收仍需相应平台环境。
