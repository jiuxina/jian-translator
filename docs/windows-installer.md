# Windows 安装器与自启动生命周期

## 行为（2026-11-19）

`desktop/patch/autostart.wxi` 注入 Pake 实际使用的 `assets/main.wxs` Product。
补丁器在打包前更新片段，重复应用不产生重复动作；丢失 Product 或损坏标记时中止。
安装器不把共享的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\IndexTranslate`
作为 MSI 组件注册表资源，因此旧安装包的组件移除不会无条件删除其他版本的启动项。

- 全新安装且启动项不存在时保持关闭。
- 安装或升级前捕获原安装目录；安装事务完成后，只有现有启动目标恰好等于原目录中的同名可执行文件，
  或等于当前安装目标时，才把仍存在的启动项改为当前 exe 的完整引号路径。
- 卸载事务完成后重新读取启动项，只删除目标恰好等于本次安装 exe 的值。大小写和斜杠形式归一化，
  不使用目录前缀匹配，便携版、其他目录或其他文件名的登记均保留。
- 旧产品因 MajorUpgrade 被移除时不运行删除动作，由新产品更新路径。
- 无效、无法解析、缺失或不相关的登记保持原状；只有“值不存在”可作为安静无操作，访问错误会使安装报告失败。

两个动作显式排在 `InstallFinalize` 之后：先判断安装更新，再判断卸载清理，条件互斥；
卸载动作通过 `After="JianUpdateAutostart"` 确定顺序，不与安装动作争用同一相对顺序。
事务在完成前失败或回滚时不会执行这两个动作，因此不会提前改写或移除启动项。

两个动作仅操作运行 MSI 的用户的 HKCU，不扫描其他用户配置；其他用户的历史登记不在此范围。
当前动作由 Windows Installer 的 JScript 引擎执行；若系统禁用了该引擎，安装会明确失败，
不能将合成测试结果视为该系统上的安装通过。安装/卸载失败后的回滚和受管设备脚本限制必须纳入发布验收。

## 验证

`node tests/verify-windows-installer.mjs` 提取实际内联动作，在内存注册表中运行，
覆盖默认关闭、旧路径迁移、环境变量、跨目录/跨版本保留、无效路径和卸载归属。
`python tests/verify-desktop-patch.py DesktopInstallerLifecycleTests DesktopAutostartPatchTests`
验证注入幂等、损坏模板拒绝，以及命令补丁仍正常应用。

发布前须用生成的 MSI 在独立测试用户环境验证：新装、同目录升级、改目录升级、普通卸载、
从便携版切换、其他安装已接管启动项、安装回滚、受限脚本策略。
使用合成路径与测试启动项；未获得授权时不要读取真实用户启动配置。
